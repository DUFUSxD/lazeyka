# Выпуск новой версии

Пользователи получают обновления так: раз в 6 часов расширение сравнивает свою версию с `extension/manifest.json` в ветке **`main`** на GitHub. Если там новее — уведомление и баннер с пунктами из `CHANGELOG.md`; кнопка «Обновить» скачивает архив `main` и подменяет файлы. Значит, **всё, что попало в `main`, — это и есть релиз.**

## Чек-лист

1. Работай в ветке, не в `main`.
2. Подними версию в `extension/manifest.json` (`"version": "X.Y.Z"`):
   - исправления — `1.2.1 → 1.2.2`,
   - новые возможности — `1.2.x → 1.3.0`.
   Сравнение числовое по частям (`1.10.0` новее `1.9.9`).
3. Добавь раздел в начало `CHANGELOG.md`:
   ```markdown
   ## 1.3.0
   - Коротко и по-человечески: что поменялось для пользователя
   - Первый пункт попадает в уведомление, первые четыре — в баннер
   ```
   Заголовок строго `## X.Y.Z` — по нему ищутся пункты. Пользователь увидит пункты всех версий новее своей.
4. `node test.mjs` и `node e2e.mjs <mihomo.exe>`.
5. Если трогал `host.ps1`, `mihomo.ps1`, `install.ps1` или поток обновления — [ручная проверка](#проверка-обновления-перед-выпуском).
6. PR → слить в `main`.
7. Проверь, что GitHub отдаёт новое: `https://raw.githubusercontent.com/DUFUSxD/lazeyka/main/extension/manifest.json`. raw-файлы кэшируются до ~5 минут — в это время «Обновить» честно скажет «GitHub ещё отдаёт старую версию».

## Чего нельзя ломать

Старые установки обновляются **старым** кодом: помощник, который скачивает новую версию, — это `host.ps1` из *установленной* версии, а расширение, которое решает «новее ли», — тоже старое.

| Что | Почему |
|---|---|
| Имя репозитория и ветки `main` | Зашиты в `RAW` (`lib.js`), `$ZIP` и `'lazeyka-main'` (`host.ps1`), `install.ps1`. Переименуешь репозиторий — GitHub перенаправит ссылки, но папка внутри архива станет `<новое-имя>-main`, и старый помощник её не найдёт. Если всё же переименовываешь — сначала выпусти версию, которая понимает оба имени. |
| Протокол помощника | `ping` / `start` / `update` и формат ответа `{ok, version, error}`. Новые команды можно только добавлять. |
| `host.bat` — одна строка с `& exit /b` | Файл перезаписывается, пока `cmd` его выполняет. |
| Ключи в `chrome.storage.local` | Переименование = потеря настроек у всех. Нужна миграция при загрузке. |
| Порты 17890 / 19090 | Записаны в `config.yaml` у пользователей, который не перезаписывается. |
| Формат строки `LZK1:` | Её могли сохранить. Новый формат — новый префикс (`LZK2:`), старый продолжать читать. |
| Путь установки `%LOCALAPPDATA%\Lazeyka\extension` | От него зависит ID расширения, а значит — доступ к помощнику. |
| Не добавлять `"key"` в `manifest.json` | Сменится ID у всех установленных копий: потеряются настройки и доступ к помощнику. |

**Новые права в `manifest.json`** у распакованного расширения выдаются сами при перезапуске (проверено на `notifications`, `favicon`, `nativeMessaging`), предупреждений пользователь не видит.

**Изменения в `mihomo.ps1`** (например, регистрации помощника) применяются сразу после обновления: помощник после копирования файлов запускает новый `mihomo.ps1`.

**Изменения в `host.ps1`** начнут работать только со *следующего* обновления (текущее выполняет старый).

## Проверка обновления перед выпуском

Безопасно, без влияния на рабочую установку — в отдельной папке с коротким путём:

1. Скачай архив своей ветки: `https://github.com/DUFUSxD/lazeyka/archive/refs/heads/<ветка>.zip`, распакуй в `C:\tmp\lzk`.
2. В `core\host.ps1` этой копии временно поменяй `$ZIP` на архив ветки и `'lazeyka-main'` на `'lazeyka-<ветка-через-дефисы>'`.
3. Положи `mihomo.exe` в `core\`, создай `config.yaml` (шаблон — в `mihomo.ps1`).
4. Поговори с помощником как браузер — из Node:
   ```js
   // node call.mjs C:\tmp\lzk ping
   import { spawn } from 'node:child_process';
   const [, , root, cmd] = process.argv;
   const p = spawn('cmd.exe', ['/d', '/c', `${root}\\core\\host.bat`, 'chrome-extension://test/']);
   const out = []; p.stdout.on('data', (d) => out.push(d));
   p.on('close', () => { const b = Buffer.concat(out); console.log(b.subarray(4).toString()); });
   const body = Buffer.from(JSON.stringify({ cmd })); const len = Buffer.alloc(4); len.writeUInt32LE(body.length);
   p.stdin.end(Buffer.concat([len, body]));
   ```
   `ping` → `start` (ядро должно жить после выхода помощника) → `update` → ещё раз `ping`/`update` (теперь работает уже скачанный помощник).
5. Для проверки в браузере: загрузи `C:\tmp\lzk\extension` в отдельном профиле (`--user-data-dir=... --disable-sync`), подмени в его `manifest.json` версию на меньшую — тогда настоящая проверка на GitHub покажет баннер, а «Обновить» пройдёт весь путь с перезапуском.
6. Убери за собой: остановить mihomo из `C:\tmp\lzk`, удалить ключи `HKCU:\Software\*\NativeMessagingHosts\com.lazeyka.host` (их перепишет `mihomo.ps1` на тестовую папку — после этого на рабочей установке выполни `mihomo.ps1` ещё раз), удалить папку.
