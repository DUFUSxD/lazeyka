# Разработка

## Что нужно

- Windows 10/11, Windows PowerShell 5.1 (есть в системе) — скрипты должны работать именно в нём, не только в PowerShell 7.
- Или macOS / Linux: `sh`, `curl`, `tar`, `gunzip`. Скрипты — POSIX sh без bash-измов: в Ubuntu и Debian `sh` — это dash.
- Node.js 22+ — только для тестов, расширению сборка не нужна.
- Chromium-браузер (Chrome, Edge).
- `mihomo.exe` для сквозного теста: `mihomo-windows-amd64-compatible-*.zip` со [страницы релизов](https://github.com/MetaCubeX/mihomo/releases) (на macOS/Linux — `mihomo-<система>-<архитектура>-*.gz` или уже скачанный установщиком `~/Lazeyka/core/mihomo`).

## Запуск из исходников

Самый честный способ — поставить как пользователь и править прямо установленные файлы:

```powershell
irm https://raw.githubusercontent.com/DUFUSxD/lazeyka/main/install.ps1 | iex
```

На macOS и Linux — `curl -fsSL https://raw.githubusercontent.com/DUFUSxD/lazeyka/main/install.sh | sh`, всё ставится в `~/Lazeyka`. Из своей копии репозитория: `LAZEYKA_FROM=<папка> sh install.sh` (на Windows — `$env:LAZEYKA_FROM` перед `install.ps1`).

Дальше правишь `%LOCALAPPDATA%\Lazeyka\extension\*` и жмёшь ⟳ на карточке Лазейки в `chrome://extensions`. Кнопки «Обновить» и «Запустить ядро» работают, потому что расширение загружено из папки, под которую прописан помощник.

Можно загрузить расширение прямо из клона репозитория («Загрузить распакованное» → `extension\`). Всё, кроме помощника, будет работать с уже запущенным ядром (secret возьми из `%LOCALAPPDATA%\Lazeyka\core\config.yaml`). Кнопки «Обновить»/«Запустить ядро» покажут запасной путь с командой: ID расширения из другой папки не совпадает с `allowed_origins` в `host.json`. Это ожидаемо.

> Если у браузера включена синхронизация, временные профили для тестов лучше запускать с `--disable-sync --disable-features=msImplicitSignin` — иначе Edge сам войдёт в аккаунт Windows и подтянет твои расширения (в том числе чужие VPN, которые перехватят прокси).

Отладка:
- **popup** — правый клик по окну Лазейки → «Просмотреть код»;
- **service worker** — `chrome://extensions` → Лазейка → ссылка «служебный сценарий» / «service worker»;
- **ядро** — см. [troubleshooting.md](troubleshooting.md).

## Тесты

```powershell
node test.mjs                         # ~0.1 с, без сети и ядра
node e2e.mjs C:\path\to\mihomo.exe    # ~20 с, нужен интернет
```

**`test.mjs`** — чистая логика из `lib.js`:
- конфиг mihomo: группы, порядок правил для своих серверов, `proxy: DIRECT` у подписок, префиксы;
- разбор доменов и подписок (`norm`, `parseList`, `parseSubs`, понятная ошибка на `vless://`);
- маршрутизация: **исполняется настоящий текст PAC** в `node:vm` — так ловятся ссылки наружу из встраиваемых функций;
- причины для карточки сайта, экспорт/импорт и отказ на мусор, сравнение версий, разбор CHANGELOG;
- пороги состояния подписки (`subStatus`), сортировка серверов, разбор заголовков провайдера (`parseSubMeta`: base64, отказ на `javascript:`, переезд только https), `migrateSub`.

**`e2e.mjs`** — логика расширения против настоящего mihomo:
- поднимает два живых фейковых сервера (HTTP-прокси с туннелем CONNECT) и подписки в формате YAML и base64;
- панель подписок получает один и тот же `x-hwid`;
- проверяет реальный путь трафика через `127.0.0.1:17890`: обычный сайт → выбранный сервер, сайт со своим сервером → свой, `speed.cloudflare.com` → сервер из `SPEED`, пропавший сервер → блок, мёртвый сервер → блок (kill switch); поля потока `/traffic`;
- «Авто» сразу после заливки и **под фоновым трафиком** (регрессия 1.2.1);
- подписка через VPN, перезапуск ядра (конфиг заливается заново, выбор сохраняется), «все мертвы».

Тест занимает порты 17890/19090 и 18888/18891/18892 — **останови рабочее ядро** перед запуском. Health-check идёт на `cp.cloudflare.com`, поэтому нужен интернет.

> exe нельзя запускать из папки с путём длиннее 260 символов (MAX_PATH) — клади `mihomo.exe` во что-нибудь короткое вроде `C:\tmp\`.

### CI на трёх системах

`.github/workflows/test.yml` («Проверки») идёт на каждый PR и push в `main` на Windows, macOS и Linux:
1. `node test.mjs`;
2. установка из проверяемой ветки: `LAZEYKA_FROM=$PWD sh install.sh`, на Windows — `Get-Content -Raw -Encoding UTF8 install.ps1 | Invoke-Expression` (так же, как `irm | iex` у пользователей);
3. `node ci/check-install.mjs`: ядро отвечает; настоящий Chrome загружает расширение из папки установки (`Extensions.loadUnpacked` по протоколу отладки); его ID есть в `allowed_origins` помощника; `ping` и `start` через native messaging из service worker отвечают как надо;
4. ядро останавливается, `node e2e.mjs` идёт на только что установленном mihomo.

Почему Chrome управляется так, а не флагами — в [decisions.md](decisions.md#проверка-на-настоящем-chrome-в-ci).

### Что тестами не покрыто

Окно расширения и обновление проверялись вручную (у помощника CI проверяет `ping` и `start`, но не `update`) через Edge + DevTools Protocol (`--remote-debugging-port`). Для данных провайдера в тестовую копию `manifest.json` добавляют `http://127.0.0.1/*` в `host_permissions` (диалог разрешения по CDP не нажать), а фейковая панель отдаёт заголовки только `User-Agent: clash.meta/…` — так видно, что подмена UA работает, а обычная вкладка получает HTML. Не проверить в CI и автозапуск после перезагрузки (launchd, systemd, ключ Run), и диалог выбора папки. Если меняешь помощника, `mihomo.ps1`/`mihomo.sh` или поток обновления — прогони руками сценарий из [release.md](release.md#проверка-обновления-перед-выпуском).

## Как устроен код

**`lib.js`** — без DOM, импортируется и popup, и service worker, и тестами (функции, которые трогают `chrome.*`, тесты просто не вызывают).

| Блок | Функции |
|---|---|
| настройки | `DEFAULTS`, `load` |
| домены | `norm`, `parseList`, `parseSubs` |
| маршрутизация (встраивается в PAC) | `buildRules`, `match`, `isLan`, `decide`, `buildPac` |
| конфиг ядра | `buildConfig`, `pushConfig`, `ensureConfig` |
| API ядра | `api`, `selectServer`, `testGroup`, `health` |
| прокси браузера | `proxyState`, `applyProxy`, `proxyOff`, `toggle`, `setBadge` |
| списки и обновления | `updateBlocked`, `checkUpdate`, `newer`, `changelogSince`, `hostCall` |
| перенос | `exportSettings`, `importSettings` |

**`popup.js`** — только интерфейс. Все действия обёрнуты в `run()`: «ядро недоступно» (TypeError от `fetch`) показывает карточку с кнопкой запуска, 401 — «Неверный secret», остальное — всплывающее сообщение. Переменная `h` — сводка `health()`: `undefined` — ещё не загрузили, `null` — ядро недоступно.

**`background.js`** — таймеры, уведомления, горячая клавиша, вызовы помощника. Обновление запускается здесь, а не в popup: popup закрывается от любого клика мимо, а открытый порт к помощнику держит service worker живым.

**`i18n.js`** — переводы. Ключ — сам русский текст (`t('Сохранено ✓')`, подстановки `{0}`: `t('Доступна версия {0}', v)`), английский — в словаре `EN`; нет перевода — показывается русский. Статичный текст `popup.html` переводит `translateDom()` при открытии окна. Язык ставит `load()` из настройки `lang`.

**`countries.js`** — поиск серверов по стране (`serverFilter`). Названия стран на двух языках даёт браузер (`Intl.DisplayNames` по коду, код же даёт флаг), в файле — только разговорные синонимы и города.

## Частые задачи

**Поменять сайт или скриншоты.** Сайт — `site/` (русская страница и `en/`), картинки берутся из `docs/images` при сборке; workflow `.github/workflows/pages.yml` публикует его на https://dufusxd.github.io/lazeyka/ после слияния в `main`. Тексты сайта, `README.md` и `README.en.md` правятся вместе.

**Добавить или поменять текст.** Пиши по-русски в одинарных кавычках внутри `t()` — и добавь английский вариант в `EN` в `i18n.js`. `test.mjs` упадёт, если у русского текста нет перевода или он оказался в шаблонной строке `` `…` `` мимо `t()`. Внутренние тексты, по которым код узнаёт ошибку (`mihomo 401`, `forbidden`, `not found`), не переводятся.

**Добавить настройку.** Ключ и значение по умолчанию — в `DEFAULTS`. Поле — в `popup.html` (экран настроек), чтение/запись — в `fillSettings()` и обработчике «Сохранить» в `popup.js`. Если настройку надо переносить между компьютерами — добавить в `PORTABLE` и в проверку типов `importSettings()`. Если она влияет на конфиг ядра — в `buildConfig()` и в `mihomoKey` внутри `apply()` (иначе ядро не перезальётся).

**Изменить правила сайтов.** Только в `decide()`/`buildRules()` — popup и PAC используют одну и ту же функцию. Помни: функции, встраиваемые в PAC, не видят ничего снаружи. Добавь случай в раздел PAC в `test.mjs`.

**Поменять порты.** `PORT`, `CONTROLLER` в `lib.js`; шаблоны в `core/mihomo.ps1` и `core/mihomo.sh` (тест проверяет, что они одинаковые); `host_permissions` в `manifest.json`. У уже установленных пользователей `config.yaml` не перезаписывается — им придётся поправить его руками или удалить (создастся заново с новым secret).

**Добавить российский сервис в «напрямую».** Массив `RU` в `lib.js` (домен покрывает поддомены).

**Новая команда помощника.** Только в `switch` в `host.ps1` и в `case` в `host.sh`, без параметров из сообщения. Учти: у пользователей со старой версией новая команда появится лишь после того, как обновление уже произошло — расширение должно переживать ответ `Неизвестная команда`.

## Стиль

- Без сборки, фреймворков и зависимостей. Комментарии — по-русски, только «почему», не «что».
- `.ps1` в `core/` — UTF-8 **с BOM** (иначе Windows PowerShell 5.1 ломает кириллицу). `install.ps1` — **без BOM** (BOM ломает `irm | iex`).
- `host.bat` — одна строка, заканчивается `& exit /b` (см. [decisions.md](decisions.md#помощник-обновляет-сам-себя)).
- `.sh` — окончания строк LF (`.gitattributes`), бит исполнения в git (`git update-index --chmod=+x`), весь код в функциях, последняя строка — `main "$@"; exit` (там же, почему).
